# px — 给个人代理用的网页代理

一个部署在 Cloudflare 上的小代理，专门解决一个烦恼：

**个人 AI 代理替你上网时，老被网站的登录和授权弹窗反复打断。**

你让代理去读一个网页，它要你登录；好不容易登录完，过一会儿又弹一次。px 的做法是：登录这件事只做一次——经 px 访问的网站，登录状态由 px 统一保管好，之后再去同一个网站，不再频繁弹窗。

除此之外，它也是一个普通的网页代理：在地址前面拼一段前缀，就能经它打开网页。

## 它是怎么工作的

- px 运行在 Cloudflare Workers 上（免费额度对个人完全够用）。你把它部署到自己的 Cloudflare 账户里，绑上自己的域名。
- 打开网页的方式很直白：`https://你的域名/https/要打开的网址`，比如 `https://你的域名/https/example.com`。
- 第一次打开时，页面上只有一个小框：输入你自己设的「授权码」，回车。浏览器会记住 30 天，之后不用再输。
- 经 px 登录过一次的网站，登录状态会被分站保存好；代理里的链接、跳转都自动继续走代理，不会跳出去。
- 陌生人打开你的域名，只会看到一个普通的 nginx 欢迎页——看不出这是个代理，也进不来。全站禁止搜索引擎收录。

## 部署（不用会编程，跟着点就行）

先准备好两样东西，都是免费的：

1. 一个 Cloudflare 账户，并且有一个域名已经托管在 Cloudflare 上（域名的 DNS 由 Cloudflare 管理）。
2. 一个 GitHub 账户。

然后按顺序做：

**第 1 步：把这个仓库复制到你的 GitHub**
点本页右上角的 Fork，这个项目就有一份属于你的副本了。

**第 2 步：把名字和域名改成你的**
在你 Fork 出的仓库里，打开 `wrangler.jsonc` 文件，改两处：

- `name`：你的 Worker 名字，随便起，比如 `px`；
- `routes` 里的 `pattern`：你准备给代理用的域名，比如 `px.example.com`（这个域名要在你的 Cloudflare 账户里）。

改完点提交保存。

**第 3 步：在 Cloudflare 里把 Worker 和仓库连起来**
打开 Cloudflare 控制台 → Workers & Pages → 创建一个 Worker，选择连接到 Git（Connect to Git），选中你 Fork 的仓库。如果它让你填构建命令和部署命令：构建命令留空，部署命令保持默认，点部署。连好之后，你以后每次改完代码提交，Cloudflare 都会自动重新部署，不用你再管。

**第 4 步：设置你的授权码**
部署完成后，在 Cloudflare 控制台打开这个 Worker → 设置 → 变量和机密 → 添加：

- 名称填 `PX_KEY`，类型选「机密」，值填一串你自己编的、足够长的字符串（这就是进门钥匙，别告诉别人）。

保存后立刻生效，不用重新部署。以后想换钥匙，也是在这里改。

**第 5 步：试一下**
浏览器打开 `https://你的域名/https/example.com`，应该先看到一个输入框；输入你刚设的授权码并回车，能看到 Example Domain 的页面，就说明一切正常。

## 日常使用

**自己浏览**
输过一次码之后，打开 `https://你的域名/https/` 会有一个输入网址的框，填网址回车即可；也可以直接在地址栏拼：`https://你的域名/https/目标网址`。

**给你的个人代理用**
输码成功后的页面上，有一段写好的说明文字（在网址输入框上方），点一下就能复制。把这段文字粘贴到你的个人代理的说明里，代理就知道：抓取网页走这个代理、需要授权码时让你通过安全保险库输入、在命令行调用时带什么请求头。你不用自己组织这些话。

**在命令行或脚本里用**
不需要浏览器记住登录状态，在请求里带上授权码即可：

```
curl -H "X-Px-Key: 你的授权码" "https://你的域名/https/example.com/"
```

## 附带功能：临时中转站（/paste）

同一个 Worker 还带一个临时中转站，解决"手边有个文件或一段文本，想马上弄到另一台设备上，但各家云盘都要登录"的麻烦：

- 打开 `/paste` 是一个目录页：所有在站文件平铺列出（名字、大小、剩余时间），点开即取；也能在同页贴文本、传文件（格式不限）
- 每次上传自动在文件名前加上 Unix 时间戳（如 `1762900000-报告.pdf`），同名永不覆盖；文本不写名字时自动存为 `text-<时间戳>.md`
- 每个文件按自己的上传时间起 **30 分钟自动销毁**（另有定时扫除兜底）；目录、上传、删除用同一把 PX_KEY 把门，**下载凭链接即可、不用 key**（方便在任何设备上直接取）
- 防滥用硬顶：同时最多 200 个文件、总量 1 GB、单文件 100 MB，满了直接拒绝上传，不会无限积压

启用条件：在 Cloudflare 控制台的 R2 里先建一个存储桶（默认名 `pxnbfun`，与 wrangler.jsonc 里 r2_buckets 的 bucket_name 对上即可）。存储几乎总是空的（30 分钟就清），费用可忽略。

命令行（curl）同样可用，授权走 `X-Px-Key` 请求头：

```bash
# 传文件（PUT，路径末尾是文件名；返回一行最终链接）
curl -T 报告.pdf -H "X-Px-Key: <你的key>" https://px.example.com/paste/报告.pdf
# 传文件（表单方式）
curl -F "file=@报告.pdf" -H "X-Px-Key: <你的key>" https://px.example.com/paste
# 传一段文本
curl -F "text=要中转的文字" -H "X-Px-Key: <你的key>" https://px.example.com/paste
# 取文件（-J 用原始文件名保存）
curl -J -H "X-Px-Key: <你的key>" "https://px.example.com/paste/<目录页里的文件名>"
```

## 已知限制（先说清楚）

- px 的出口是 Cloudflare 的机房 IP。少数防护很严的网站会直接拦机房 IP（最典型的是 Google 搜索，会跳人机验证），这类网站走不通，换个搜索引擎（比如 Bing）通常就行。这不是 px 的毛病，是这类网站的一贯做法。
- 少数完全靠 JavaScript 动态生成的网页，经代理后可能显示不完整。
- Cloudflare 免费版每天有 10 万次请求额度，个人使用远远用不完。

## 安全提醒

- 授权码就是大门钥匙：设得长一点，不要写进代码，不要发到公开的地方。想换钥匙时按第 4 步改一下即可，旧钥匙立即失效。
- 没有授权码的人访问你的域名，只会看到伪装页，px 不会变成公共代理被人盗用。

## 费用

个人自用场景下，Cloudflare Workers 免费版就够，不需要付费。
